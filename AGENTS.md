# Project guidance

- Run Python commands from the repository root. `roof_classifier` and `Data` are namespace packages; use `python -m roof_classifier.train`, not direct execution of the module file.
- Install the model dependencies with `python -m pip install -r roof_classifier/requirements.txt` in a virtual environment. Verified on Python 3.13 / Apple Silicon with PyTorch 2.8.0.
- Run offline unit tests with `python -m unittest discover -s tests -v`. No tile downloads are needed for these tests.
- Training: `python -m roof_classifier.train --data-dir Data/roof_dataset_20_20 --output-dir artifacts/roof_classifier`. The output directory must be empty. Default training uses up to 128 epochs with early stopping; `--epochs 1` is available for a smoke test. Device selection prefers CUDA, then MPS, then CPU.
- Standalone export: `python -m roof_classifier.export --checkpoint artifacts/roof_classifier/best.pt --output artifacts/roof_classifier/exported.onnx`. The destination must not already exist. Export checks the ONNX graph and compares CPU ONNX Runtime against PyTorch at batch sizes 1 and 2.
- Inference: `python -m roof_classifier.predict --checkpoint artifacts/roof_classifier/best.pt --image PATH_TO_128PX_IMAGE`.
- Class order is explicitly `non_asbestos=0`, `asbestos=1`; do not use alphabetical folder ordering. ONNX accepts already-normalized float32 NCHW images and emits raw logits. Asbestos probability is `softmax(logits, dim=1)[:, 1]`.
- `Data/build_roof_dataset.py` already handles Google satellite tiles at zoom 20, a 3x3 tile mosaic and building-centered RGB 128x128 crops. It saves raw PNGs. The classifier applies the user-specified fixed mean/std, not the older normalization recommendation in generated dataset config files.
- Roofs no longer need to fit entirely within the crop: the upper size/margin filter and `--crop-margin-px` option were removed at the user's request. Crops remain 128x128 without resizing; larger roofs may be clipped. Minimum roof area/side filters remain. New dataset configs record `require_full_roof_in_crop: false`; existing datasets and their provenance configs are not modified retroactively.
- Dataset collection applies the same quality thresholds to both classes before saving any crop: roof-footprint coverage, green dominance globally/over the roof, Laplacian sharpness, contrast and edge density. The largest polygon is selected and its centroid is used only if inside the roof; otherwise an interior point avoids courtyards and gaps. Accepted metadata includes `roof_polygon_px`, `center_method` and quality metrics. Rejected candidates are replaced, not counted toward requested totals; `quality_rejections_<class>.csv` and `rejected_<class>.jpg` aid review.
- Quality filtering is heuristic, not a semantic roof detector or proof of native tile resolution. It can reject green/smooth roofs and miss non-green empty lots or stale footprints. Do not claim guaranteed roof presence without manual review or a separately validated roof detector.
- Audit existing crops without changing them: `python Data/build_roof_dataset.py --audit-dataset Data/roof_dataset_1000_500 --output-dir artifacts/roof_quality_audit`. The output folder must be empty. Older metadata lacks footprints, so this audit explicitly uses the central 64x64 region as a fallback; newly generated data uses the actual projected footprint. Use `--min-sharpness`, `--min-contrast`, `--min-edge-density`, `--max-green-fraction`, `--max-roof-green-fraction`, `--min-roof-fraction` to configure thresholds. Record threshold changes and review rejection previews rather than silently relaxing filters.
- Dataset-only verification, without PyTorch: install `Data/requirements-dataset.txt` and run `python -m unittest discover -s tests -p test_dataset_quality.py -v`.
- The current regenerated quality-filtered 1000+500 dataset is `Data/roof_dataset_1000_500_quality_v2`; its audit is `artifacts/roof_quality_audit_filtered_v2`. The default minimum sharpness is 40, raised after visual review of the weakest accepted crops. The earlier `roof_dataset_1000_500_quality` used a threshold of 20 and is only an intermediate version. Existing checkpoints in `artifacts/roof_classifier_1000_500` were trained on the original unfiltered dataset, not either regenerated version.
- The 20+20 dataset is a pipeline smoke-test dataset, not evidence of production accuracy. Negative labels inferred from absence in GeoAzbest are not verified asbestos-free roofs.
- Keep generated checkpoints, ONNX files, tile caches and large source datasets out of commits unless explicitly requested.
- The 1000+500 dataset is at `Data/roof_dataset_1000_500`. The seed-2022 stratified split contains 1050 training, 225 validation and 225 test images (700/350, 150/75 and 150/75 by class). Train it with `python -m roof_classifier.train --data-dir Data/roof_dataset_1000_500 --output-dir artifacts/roof_classifier_1000_500` using a new empty output directory.
- Training audits image hashes and CSV metadata before fitting. Conflicting labels or identical images/building identities across splits are rejected. `data_audit.json` records the dataset fingerprint and cross-split neighbors within 50 m; random stratification is not a geographic holdout.
- `history.json` is updated atomically after every epoch. `best.pt` is also saved atomically and is selected only by validation loss. `metrics.json` and `test_predictions.csv` are produced after reloading the best checkpoint. The test set is not used for model selection or threshold tuning.
- Evaluation includes precision, recall and F1 for each class, balanced accuracy, ROC AUC, average precision and Brier score. Compare against the majority baseline: on the 1000+500 test split, always predicting non-asbestos yields 66.67% accuracy but zero asbestos recall. Metrics use the fixed decision rule `p(asbestos) > 0.5`, matching argmax's negative-class tie break.
- FastAPI backend: `fastapi_backend/README.md` documents the frontend contract, deployment and environment variables. Run from the repository root with `python -m uvicorn fastapi_backend.app:app --host 127.0.0.1 --port 8001 --workers 1`. Install `fastapi_backend/requirements.txt`; verify with `python -m unittest discover -s fastapi_backend/tests -v`. Python 3.11+ is required.
- Backend inference uses the ONNX from `artifacts/roof_classifier_quality_v2_server/model.onnx` (the server-trained quality_v2 model, best epoch 24), not the earlier model. It shares centering/quality checks and `QUALITY_DEFAULTS` with `Data/build_roof_dataset.py`; the backend folder is not standalone without that shared module.
- `fastapi_backend/data/buildings.sqlite` is a read-only runtime database containing all 2,585,219 valid OSM building polygons in the imported Mazowieckie snapshot, indexed with R-tree. Exact polygon intersection selects buildings; exceeding request limits returns 413 rather than silent truncation. Each selected building stays in the GeoJSON response even if its score is null due to quality or imagery errors.
- Backend token files live under ignored `fastapi_backend/runtime/` and must never be logged, committed or embedded in documentation. POST /v1/analyze requires Bearer authentication. Use HTTPS or an SSH tunnel for non-local access. CORS is not authentication. Generated SQLite databases, caches and runtime logs are also excluded from backend Git tracking.
